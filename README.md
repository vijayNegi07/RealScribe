# Real-Time Audio Transcriber

A full-stack real-time audio transcription application that captures
microphone audio in the browser, streams raw PCM audio to a Node.js
WebSocket server, forwards it to Deepgram for real-time speech-to-text
processing, and sends transcription results back to the Next.js
frontend.

## Features

-   Real-time microphone audio capture in the browser.
-   Audio processing using the Web Audio API and `AudioWorklet`.
-   Conversion of browser audio samples from `Float32Array` to 16-bit
    PCM.
-   Browser → Node.js WebSocket communication for low-latency audio
    streaming.
-   Node.js → Deepgram WebSocket communication.
-   Real-time Deepgram transcription with:
    -   Interim results
    -   Final results
    -   Speaker information/diarization support
    -   `nova-3` model
    -   English language
-   Node.js → Browser WebSocket communication for transcript updates.
-   React UI that displays live transcription.
-   Separate handling of finalized and interim transcript text.
-   Complete finalized transcript is retained in frontend state.
-   Live transcript viewport automatically follows the newest content.
-   Clean microphone/audio resource cleanup when recording stops.
-   AI summary API using Next.js and Gemini.
-   Summary endpoint accepts the complete transcript from the frontend
    and returns a summary string.

# Architecture / Approach

The application is intentionally split into two server-side
responsibilities:

``` text
                         ┌─────────────────────┐
                         │      Next.js        │
                         │                     │
                         │  Summary API        │
                         │  /api/summary       │
                         │         │           │
                         │         ▼           │
                         │      Gemini         │
                         └─────────▲───────────┘
                                   │
                                   │ HTTP
                                   │
┌──────────────┐       WebSocket   │
│              │ ──────────────────┼──────────────┐
│   Browser    │                   │              │
│              │                   │              ▼
│ Microphone   │              ┌────┴─────┐    Deepgram
│      ↓       │              │ Node.js  │
│ AudioWorklet │              │ WebSocket│
│      ↓       │              └──────────┘
│ PCM Int16    │
└──────────────┘
```

## Real-Time Transcription Flow

### 1. Microphone capture

The browser requests microphone access using:

``` js
navigator.mediaDevices.getUserMedia({
  audio: true
});
```

The resulting `MediaStream` is passed into an `AudioContext`.

### 2. Audio processing

An `AudioWorklet` processes microphone samples in real time.

The application uses PCM audio rather than `MediaRecorder` WebM/Opus
chunks because the transcription pipeline expects raw PCM audio
configured as:

``` text
Encoding: linear16
Sample rate: 16000 Hz
Channels: 1
```

The browser converts the `Float32Array` samples generated by the Web
Audio API into signed 16-bit PCM samples.

### 3. Browser → Node.js

The PCM buffer is sent as binary data through a WebSocket:

``` text
Browser
   ↓
WebSocket
   ↓
Node.js
```

The Node.js server receives each audio chunk.

### 4. Node.js → Deepgram

For each browser WebSocket connection, Node.js creates one Deepgram
streaming connection.

The Deepgram connection is configured with the `nova-3` model and
real-time transcription settings.

Audio chunks received from the browser are forwarded to Deepgram.

### 5. Deepgram → Node.js

Deepgram sends transcription events back to Node.js.

The application distinguishes between:

-   Interim results --- temporary transcription that can change.
-   Final results --- confirmed transcription.

### 6. Node.js → Browser

Node.js sends transcription results back through the existing browser
WebSocket:

``` json
{
  "type": "transcript",
  "transcript": "Hello this is a test",
  "isFinal": true,
  "speaker": 0
}
```

The React frontend updates its state accordingly.

### 7. Transcript UI

Finalized transcript segments are stored in the complete transcript
state.

The UI only shows a limited live viewport and automatically scrolls to
the newest content. Older content remains stored in state and is not
deleted.

Make sure the following are installed:

-   A Google/Gemini API key
-   A modern browser with microphone support

# Running the Application

The application has two servers that need to run simultaneously.

## Start the Node.js WebSocket server

From `realtime-server`:

``` bash
npm run dev
```

The WebSocket server runs on:

``` text
ws://localhost:8080
```

The browser connects to this server to stream microphone PCM data.

## Start the Next.js application

From `web`:

``` bash
npm run dev
```

The Next.js application normally runs on:

``` text
http://localhost:3000
```

Open the application in a browser and allow microphone access.

# AI Summary API

The summary functionality is handled by the Next.js application rather
than the real-time Node.js server.

The endpoint is:

``` text
POST /api/generate-summary
```

Request:

``` json
{
  "transcript": "Complete transcript goes here..."
}
```

Response:

``` json
{
  "summary": "A concise summary of the transcript..."
}
```

The complete finalized transcript is sent to the Next.js API when the
user requests a summary.

The AI model is responsible only for generating the summary; it is not
involved in the real-time audio streaming path.

# Assumptions

## Browser audio support

The application assumes that the browser supports:

-   `getUserMedia`
-   Web Audio API
-   `AudioWorklet`
-   WebSocket

A modern Chromium-based browser is recommended during development.

## Microphone permission

The user must grant microphone permission.

In production, microphone access requires a secure context such as
HTTPS.

## Audio format

The application assumes that the browser-side audio pipeline produces:

``` text
Linear PCM
16-bit
16000 Hz
Mono
```

This matches the configuration sent to Deepgram.

## One active recording session

The current design assumes one active recording session per browser
connection.

Multiple simultaneous recording sessions would require additional
session management.

## API keys remain server-side

Deepgram and Gemini API keys should never be exposed to the browser.

The browser communicates with the application's servers instead.

## Transcript storage

The current frontend keeps the complete transcript in application state.

Persistent database storage can be added later if transcript history is
required.

# Why Two Servers?

The Node.js server is dedicated to the real-time audio pipeline:

``` text
Browser
   ↕
WebSocket
   ↕
Node.js
   ↕
WebSocket
   ↕
Deepgram
```

This keeps the long-lived WebSocket connection separate from normal
application/API functionality.

Next.js handles regular application functionality such as:

``` text
Authentication
API routes
AI summary generation
Database operations
Frontend
```

This separation makes the architecture easier to maintain and scale.

------------------------------------------------------------------------

# Connection Lifecycle

When recording starts:

``` text
1. Browser requests microphone access
2. Browser creates AudioContext
3. AudioWorklet starts processing audio
4. Browser opens WebSocket to Node.js
5. Node.js creates a Deepgram connection
6. Node.js waits for Deepgram to become ready
7. Browser starts sending PCM audio
8. Node.js forwards audio to Deepgram
9. Deepgram returns transcription results
10. Node.js forwards results to Browser
11. React updates the UI
```

When recording stops:

``` text
1. Stop microphone tracks
2. Disconnect AudioWorklet
3. Close AudioContext
4. Close browser WebSocket
5. Node.js detects browser disconnect
6. Node.js closes the Deepgram connection
```

The Deepgram connection is created once per browser WebSocket connection
rather than once per audio chunk.

------------------------------------------------------------------------

# Interim vs Final Transcription

Deepgram can produce results before they are finalized.

For example:

``` text
Interim: Hello
Interim: Hello this
Interim: Hello this is
Final:   Hello this is a test
```

The application therefore keeps two concepts:

``` text
Final transcript
+
Current interim transcript
```

Interim text is displayed as temporary text, while final text is added
to the complete transcript.

This prevents repeated interim results from being permanently appended.

------------------------------------------------------------------------

# Error Handling

The application includes handling for:

-   Browser WebSocket errors
-   Browser WebSocket disconnections
-   Deepgram connection errors
-   Deepgram connection closures
-   Attempts to send audio before Deepgram is ready
-   Microphone cleanup
-   Invalid/missing transcript data for the summary API

The Deepgram readiness state is maintained per browser connection so
multiple browser connections do not share the same connection state.

# Current Limitations

-   Transcript persistence is not yet implemented.
-   Authentication/authorization for transcript access may be added
    later.
-   The current application is primarily designed for one active
    microphone stream per client.
-   The summary endpoint currently receives the transcript directly from
    the frontend.
-   Production deployment requires appropriate HTTPS/WSS configuration.
-   Production deployment may require a separately hosted persistent
    WebSocket server depending on the hosting platform.


The application uses a dedicated real-time Node.js WebSocket server for
low-latency audio streaming and Deepgram transcription, while Next.js
handles standard application APIs and AI-powered summary generation.

The core real-time pipeline is:

``` text
Microphone
    ↓
AudioWorklet
    ↓
16-bit PCM
    ↓
Browser WebSocket
    ↓
Node.js WebSocket Server
    ↓
Deepgram
    ↓
Transcript
    ↓
Node.js
    ↓
Browser
    ↓
React UI
```

The AI summary pipeline is:

``` text
Complete Transcript
       ↓
Next.js /api/summary
       ↓
Gemini
       ↓
Summary
       ↓
React UI
```
